Player Movement 2D

Setup

Innanzitutto, inserisci nella scena un GameObject che rappresenti il player. Aggiungi un componente Rigidbody2D e un Collider2D (come BoxCollider2D o CircleCollider2D) al GameObject del player. Assicurati di impostare il Rigidbody2D su "Dynamic" e di abilitare la gravità se desideri che il player sia influenzato dalla fisica. 

using UnityEngine;

public class PlayerMovement : MonoBehaviour
{
    public float moveSpeed = 5f;
    private Rigidbody2D rb;
    private Vector2 movement;

    void Start() => rb = GetComponent<Rigidbody2D>();

    void Update() => HandleInput();

    void FixedUpdate() => Move(); 

    void HandleInput()
    {
        //Qui viene gestito l'input del giocatore per il movimento, in questo caso si usa il vecchio input system di unity.
        movement.x = Input.GetAxis("Horizontal");
        movement.y = Input.GetAxis("Vertical");

        movement = movement.normalized;
    }

    void Move()
    {
        rb.linearVelocity = movement * moveSpeed;
    }
}

Perchè viene Usato FixedUpdate per la fisica?

FixedUpdate() viene eseguito a intervalli di tempo costanti definiti dal parametro Fixed Timestep nelle Project Settings. Per impostazione predefinita viene chiamato ogni 0,02 secondi, cioè circa 50 volte al secondo, ma questo valore può essere modificato. Poiché il motore fisico di Unity viene aggiornato durante FixedUpdate(), è buona pratica applicare qui tutte le operazioni che coinvolgono il Rigidbody2D(), come l'assegnazione della velocità o l'applicazione di forze. Update(), invece, viene eseguito una volta per ogni frame renderizzato. Di conseguenza, la sua frequenza dipende dagli FPS del gioco: a 60 FPS verrà chiamato circa 60 volte al secondo, mentre a 144 FPS circa 144 volte. Per questo motivo Update() è il posto ideale per leggere l'input del giocatore, mentre FixedUpdate() è quello corretto per applicare il movimento fisico.
